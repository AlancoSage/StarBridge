# 玩家管理

适用于 Myrinbot Bot **0.6.19** 与 Paper / Spigot / Folia 游戏插件 **0.5.3**。Forge / NeoForge / Fabric 需使用[对应版本的模组](mod-game-ends.md)。

## 用途

按真实 UUID 保存玩家档案，汇总玩家名、最近 IP、手动归属地、QQ 绑定与到访服务器。管理员可搜索、添加、备注和清理档案，也可对已上报的玩家执行踢出、永久封禁、解封及白名单操作。

档案保存在本地 SQLite，游戏服务器断线或移除后仍可查看已有资料。IP 来自游戏服务器看到的连接地址，经过代理时可能是代理地址；归属地仅由管理员手动填写，Myrinbot 没有自动查询 IP 地区的功能。后续记录到新的 IP 时，会清空原归属地。

## 使用前提

- 用服主账号的用户名和密码登录面板，或使用具备「玩家管理」权限的团队管理员账号。
- 游戏端正常连接并上报玩家管理能力和目标玩家 UUID，才能执行游戏管理。
- 踢出需要玩家当前在线；历史档案仍可查看，但没有可用上报记录时「游戏管理」不可用。
- 手动新增或绑定前，取得真实玩家 UUID 并核实身份，避免把同名账号当成同一个人。

## 面板操作步骤

### 查询与编辑档案

1. 进入「成员 → 玩家管理」。
2. 用「玩家名 / QQ」「UUID」「IP 地址」「归属地」「绑定状态」「到访服务器」「游戏状态」筛选，点击「搜索」；点击「清空」恢复全部结果。
3. 使用「每页」与「上一页」「下一页」浏览。点击玩家行的「详情」。
4. 在详情中修改「归属地」「备注」，点击「保存档案」。已有档案的玩家名、UUID 和最近 IP 由游戏端记录，面板中为只读。

### 新增与管理绑定

1. 点击「＋ 新增玩家」，填写真实玩家名和 UUID。IP、归属地与备注可按需填写。
2. 点击「创建档案」。这里只建立本地记录，不创建 Minecraft 存档。
3. 打开详情，在「绑定账号」选择服务器并填写 QQ，核实身份后点击「添加绑定」。解除单服绑定使用该条记录旁的「解绑」。

| 字段 / 参数 | 格式与限制 | 说明 |
| --- | --- | --- |
| 玩家名 | 1–16 位字母、数字或下划线 | 使用实际 Java 版玩家名 |
| UUID | 合法的真实玩家 UUID | 每个 UUID 一份档案；不同 UUID 不按同名合并 |
| 最近 IP | 合法 IPv4 / IPv6，可留空 | 新增时可填，后续由游戏端更新 |
| 归属地 | 最多 120 字 | 手动填写地区或运营商，无自动查询 |
| 备注 | 最多 1000 字 | 管理员记录；避免写入密码等凭据 |
| 每页条数 | 10、25、50、100 | 默认 25；本页全选只选择当前页 |
| 踢出 / 封禁原因 | 可选，最多 120 字，单行 | 提交前阅读操作影响 |

### 执行游戏管理

1. 在详情「到访记录与游戏管理」中，找到目标服务器，点击「游戏管理」。
2. 核对玩家与服务器，选择「管理操作」。
3. 阅读影响说明；踢出、封禁可填写「操作原因（可选）」。
4. 点击「执行操作」，展开列表下方「最近游戏操作」查看回执。

| 操作 | 实际影响 |
| --- | --- |
| 踢出服务器 | 断开当前连接，玩家仍可重新加入 |
| 永久封禁 | 禁止该 UUID 加入当前服，并断开当前连接 |
| 解除封禁 | 移除该玩家在当前服的封禁记录 |
| 加入白名单 | 添加到当前服白名单；是否限制入服取决于游戏服务器白名单开关 |
| 移出白名单 | 移除当前服白名单资格，不主动断开现有连接 |

这些操作按服务器生效，通过游戏端 API 使用 UUID 执行。面板权限与群聊的预设控制台命令名单分别管理。跨多台服处罚见[社区管理](community-operations.md)。

### 解绑与删除

列表中的「解绑」解除该玩家在全部服务器的绑定；选择本页玩家后可点击「批量解绑」。详情中一条绑定旁的「解绑」只处理该服务器。

点击「删除」或「批量删除」前核对确认框。删除清理本地档案、到访记录和全部绑定，并撤销尚未执行的玩家管理任务；不会删除游戏存档或封禁玩家。普通心跳不会立即重建已删除档案，玩家再次入服或管理员重新新增同 UUID 后可重新记录。

## 游戏与 QQ 命令示例

档案由游戏端上报，无需玩家输入建档命令。测试玩家正常进入游戏后，在面板点击「刷新」检查其记录。

若需要让玩家自行关联 QQ，在游戏内输入：

```text
/qbind
```

随后在对应服务器的关联群发送本次验证码，再查询：

```text
绑定 A1B2C3D4
我的绑定
在线
```

`A1B2C3D4` 仅为格式示例。启用了游戏登录时，玩家必须先登录才能获取绑定码。面板的封禁、踢出等操作使用上述按钮，不需要在群里输入玩家管理指令。

## 预期结果

同一 UUID 的多服记录汇总到一份档案。列表显示资料和到访状态，详情显示每台服的已上报信息；断线服务器的当前状态会变为未知，历史资料继续保留。

点击「执行操作」后先显示「等待执行」，收到游戏端回执后才显示「已完成」或「执行失败」。60 秒未确认显示「结果未确认」，应检查游戏端实际状态后再决定重试。服务器连接、路由或权限配置改变可能撤销待执行任务。

## 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| 没有玩家档案 | 清空筛选，检查游戏端连接；让玩家正常入服后点击「刷新」；确认没有只查看某台历史服 |
| 「游戏管理」按钮不可用 | 检查服务器连接、新版游戏端与目标玩家当前上报记录；只有手动档案或绑定记录不足以执行 |
| 页面提示只上报最近 500 位 | 插件单次上报最近 500 位已知玩家，在线玩家优先；此前已保存的档案仍保留，目标玩家重新入服后再查 |
| 新增提示 UUID 已有档案 | 直接搜索该 UUID 并查看详情，不要创建另一份同名记录 |
| IP 与预期不同 | 检查代理转发与游戏服观察到的地址；Myrinbot 不会根据 QQ 或邮箱推算 IP |
| 手动归属地消失 | 检查玩家是否换了 IP；新 IP 不沿用旧地址的归属地 |
| 保存提示档案已被修改 | 重新打开详情，读取最新内容后再保存，避免覆盖其他管理员的修改 |
| 操作长时间等待或结果未确认 | 先核对游戏端日志、封禁和白名单实际状态，再决定重试；不能把提交成功当作执行成功 |
| 加入白名单后仍不能进服 | 检查游戏服封禁、白名单开关和登录要求；加入白名单不会自动解封或完成登录 |
| 删除后玩家再次出现 | 玩家重新入服会重新记录；本地删除不禁止入服 |

玩家档案包含 QQ、IP 等个人信息。排查截图遮盖这些字段和邮箱、令牌，不要把管理员详情作为公开网页内容。
