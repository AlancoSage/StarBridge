# StarBridge 0.6.9

- 游戏插件升级为 `StarBridge-0.5.2.jar`，管理面板新增 nLogin、LoginSecurity、LibreLogin 接入选项，与原有 AuthMe、内置及自动引擎一起配置。自动模式按每台游戏服实际启用的插件选择；同服同时启用多个已适配的登录插件时拒绝放行，指定插件缺失或 API 不匹配也不会回退。
- LoginSecurity 通过公开异步会话 Action 接口同步登录，新建原生账号使用随机内部凭据；已有账号首次验证原密码。注册后继续执行原插件登录流程，完成状态恢复再解除星桥限制。原插件关闭注册或开启注册验证码时不会绕过；新账号创建回执可跨提前断线保存，但不沿用旧连接认证。
- LibreLogin 首次使用原生注册或登录后关联，不新建或覆盖原生密码；后续同名、同 UUID 的可信账号可由星桥密码或 QQ 请求授权。当前 Paper 端没有可用 TOTP 校验器，带有 TOTP 密钥的账号拒绝接入，避免把仅密码登录误认成完整二次验证。
- nLogin 使用原生认证观察模式，每次连接同时完成星桥证明与 nLogin 原生注册、密码或其额外验证；不创建不可知的随机密码，不调用强制登录接口。不把提交公开 `requestLogin` 请求当作登录成功，只有原生认证状态才作为完成依据。
- 三种新增适配器均仅面向普通 Bukkit 后端，LibreLogin 需要 Paper 与 Java 21；代理端不在接入范围。Folia 保留内置与自动模式，拒绝所有未经区域线程验证的外部登录插件。Forge / NeoForge / Fabric 继续使用内置或自动引擎，混合部署选择自动。
- 新增适配保留账号所有权、UUID、连接对象、nonce 与设置版本检查。退出原生会话采用断开后重连，避免异步退出尚未完成时误报成功。插件由服主自行安装，不随星桥分发。
- Bot、独立官网及二十四个游戏模组继续通过私有 Release 分发，提供二十八个附件；登录接入步骤、实际验证组合与限制同步至文档。
- nLogin 使用 `/starbridge:login` 或 `/starbridge:ql` 完成星桥证明，再用原生 `/login` 或 `/register`；需合并原插件命令白名单并开放星桥聊天提示。明确命名空间始终交给星桥，普通原生命令只有符合认证阶段才由星桥允许；原插件自身可能更早处理注册，仍不能单独解除星桥限制。
- 修复适配器快速重载时创建回执覆盖其他账号记录的问题，共享身份记录并原子合并持久化；常规认证只读取内存。

验证：Python 251 项通过；新增适配器隔离检查共 107 项，含并发与重载记录回归；Java 8 实际运行兼容检查解析 101 个 Bukkit 引用，登录事件、命令密码脱敏及 Folia 隔离 33 项通过。待发布游戏 JAR 在 LoginSecurity 3.3.1 / Paper 1.21.8 build 60 实服 23 项、nLogin free 2.0.24 / 同核心 16 项、LibreLogin 0.24.0 / Paper 1.21.4 build 232 实服 26 项、Folia 1.21.8 build 6 实服 35 项验证。

实服使用离线协议客户端；QQ 传输模拟。LoginSecurity 的星桥 HTTP 返回使用隔离后端，其他组合运行实际星桥账号后端。nLogin Premium 专属验证、全部历史插件版本和所有核心组合不在本次实服检查范围。24 个未改动的原生模组复用上一版已核验的构建字节，发布前核对完整部署包及 SHA256。
